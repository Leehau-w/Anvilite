## 产品方向与范围

Anvilite 正在从游戏化任务工具走向个人工作、生活管理面板。任务、习惯、流程、分类和成长记录是已有能力；完整信息架构和 UI 方案尚待用户描述，不能把这个方向直接当作已批准的改版需求。

当前交付：v0.4.2包含Mind Elixir、任务/子任务关联及待反馈排序/Enter修复，已完成1019项和浏览器验证；用户已授权当前支线的代码、tag、Release和Windows安装包发布，状态与产物见v0.4.2发布记录。

- 习惯是具有周期特性的特殊任务。编辑、右键、子项、排序、撤销等共同行为保持一致，周期、次数、跳过等差异保留。
- 用户文案用“分类 / Category”，不是“领域 / Domain”或“世界地图 / World Map”。代码中的 area、worldmap 是历史名称，不为改文案做无关重命名。
- 档案馆是特殊汇总视图，不能套用普通分类的全部信息。
- SOP 默认收起详情。用户要求收紧的是未展开详情时“添加子步骤”与上方内容的距离，不能误改成标题与详情之间的距离。
- 成长反馈服务于实际工作；不自行增加惩罚、损失矿石等规则。现有习惯连续次数衰减属于历史行为，若调整需单独明确规则。

## 实现约束

1. 检查 git 状态，读相关类型、store、调用 UI 和已有测试；保留用户改动。
2. 先明确复现入口，区分任务/习惯、列表/Dashboard/抽屉、详情展开/收起、完成/未完成、中英文。
3. 复用组件、纯函数和样式变量，避免把同一业务操作复制到多个 UI；不能用持续叠加负 margin 代替定位布局来源。
4. Zustand selector 不应每次返回新数组或对象而没有稳定缓存或相等比较；注意 effect 更新和渲染循环。
5. 表单内非提交按钮显式 type="button"；输入法组合输入时 Enter 不得触发提交。区分草稿和即时写入，取消语义一致。
6. 文案同步更新 zh.ts、en.ts；状态不能只靠颜色表达。

## 数据验收约束

以下是修复目标，不表示当前版本全部满足：

- 编辑标题、日期、用时不改变完成状态、子项或历史奖励。
- 完成父项递归完成子项；撤销有明确且可重复验证的恢复规则。
- 完成与跳过独立记录；去游戏化后完成、撤销、删除不发放或扣回任何奖励。旧奖励数据只作兼容，真实完成记录及可恢复的习惯周期快照仍通过稳定ID关联，不能把奖励字段连同业务快照一起删掉。
- 事件通过稳定实体 ID 和完成记录 ID 关联，不能靠翻译标题或 includes 匹配。
- 周期变化统一处理状态、次数、子项和计时；使用本地日历，覆盖午夜、恢复窗口和夏令时。
- 备份校验记录、嵌套结构和版本；恢复保留各 store 版本，防止部分写入。迁移和恢复必须有备份/回滚方案。
- 同步失败不能宣称成功，不用用户真实数据做覆盖式测试。

## 验证

按风险选择验证，不把 TypeScript 通过当作 UI 验收。

```powershell
npm test
npm run typecheck
npm run build
```

审查场景已移入 src/stores/reviewRegression.test.ts，断言正确行为。typecheck 必须显式检查 app 和 node 两个子项目；根 tsconfig 的空 files 不代表业务代码已通过检查。

- Store 测试直接调用生产 action，不复制实现。createTaskFromSOP.test.ts 已改为调用实际 store。
- 使用内存 localStorage 和固定时钟；安装的 Zustand 读取 window.localStorage，只 stub 全局 localStorage 不足以测试 hydration。
- UI 改动验证点击、键盘、事件传播和截图；布局覆盖最小窗口 900×600、常用桌面、长标题、多层子项及中英文。环境限制时明确说明，不能宣称已经验证视觉效果。
- 高风险修改覆盖完成/撤销、同名/改名、跳过、跨天/跨周、导出再导入和多段计时；不访问真实账号数据。

用户文档只描述已交付能力。发布要核对代码、文档、标签、安装包来自同一提交；打包成功不等于实际安装运行通过。
