# 本机 stdio MCP 首版与验收

日期：2026-10-23。分支codex/legacy-review，基于18a9108（v0.3.3）的现有修复及去游戏化代码。只在该支线实现；未改版本、提交、推送、发布或替换安装包。

## 交付范围

用户明确批准本机stdio MCP，支持任务、习惯和流程的读取与操作、读写权限、回归验证、防重复及防覆盖。首版19个Tools；不接入HTTP服务、任意脚本、通用文件访问、原始setState或直接编辑Electron底层存储。

- 任务：list/get/create/update/action；业务action为complete/undo/wait/resume/start/pause/delete/restore及timer_start/pause/stop。
- 习惯：list/get/create/update/action；包含complete/skip/undo、pause/resume/archive、soft delete/restore及timer_start/pause。
- 流程：list/get/create/update/action；包含delete/copy/move/instantiate，以及文件夹list/create。系统来源move沿既有copy-out规则；instantiate必须同时具有流程和任务写权限、校验两个版本。
- get_context返回当前账号、会话、已授权能力、集合版本、分类与限制；operations_get查询持久操作回执。

用户入口与配置方法见 [MCP使用说明](../../docs/mcp.md)。默认关闭，首次启用只读；三域读写独立。修改权限旋转pipe/token，需重新复制并重连；关闭/重载/换号/崩溃吊销旧会话。凭据只在主进程会话及当前设置配置中，不进入备份或日志。

## 架构及一致性

本机Agent客户端 → 官方SDK stdio子进程 → 带随机凭据的本机named pipe → Electron可信main-frame IPC → 已完成hydration的当前renderer业务service → 既有store actions。

mcp/使用独立package-lock/node_modules，官方server/client SDK固定2.3.1；不通过根junction安装依赖。独立产物dist-mcp/server.cjs打包SDK，复制配置使用当前Electron的Node模式运行；原应用打包配置将该产物放入resources/mcp。原生验证使用开发Electron，可执行安装包尚未单独打包安装验收。

写入具有requestId和expectedVersion。版本包含完整业务内容（含子项）、账号/会话、本地日期、分类信息和持久基准的opaque摘要；SHA计算等待及main lease校验后，同步再次比对。其它页面/窗口、导入raw写入与旧live内存不一致时拒绝继续，不能铸造新版本来覆盖导入值。私有raw只本机比较，不出响应、回执或日志，已有canary测试。

renderer内写入串行；业务执行前先持久写pending意图，执行并验证实际落盘后提交committed结果。相同请求原样重试重放原结果，不再次执行；相同ID不同参数拒绝。业务或回执结果不确定时保留pending，并暂停本renderer session的新写入；operations_get可读。回执不随普通业务备份迁移，换会话的版本失效避免旧请求直接继续执行。没有跨进程崩溃的原子事务保证，不以超时/断线推断未执行，不自动更换ID重试。

流程步骤更新按同父级稳定ID合并，遗漏说明、孩子、同级步骤保留，无ID节点追加；不能借patch隐式移动、删除、重排。folderId修改统一走move，避免绕过系统来源复制规则。习惯pause/resume等严格校验状态与周期关闭标记，不能通过状态循环重复完成。

首版最大100条/页、2000条持久回执、1MiB管道帧、128000字符业务请求；满额/存储失败停止写入，不清掉旧去重记录。Win32本机pipe配随机凭据，stdio客户端拒绝远程UNC及TCP目标；未做跨平台实际设备验收。
