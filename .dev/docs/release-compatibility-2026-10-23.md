# v0.4.0 发布前数据兼容性验收

日期：2026-10-23。按用户最新要求，本次正式兼容范围为 **v0.3.0 及之后版本升级到 v0.4.0**；不扩展或承诺 v0.3.0 以前的平铺数据结构兼容，也不承诺新数据可在旧程序中降级使用。

## 旧数据来源与可复现性

新增固定合成夹具位于 src/test/fixtures/：

- release-v0.3.0-storage.json：来自标签 v0.3.0，提交 046b9e0de30b8724f1b95a4c12073d073bec980e。
- release-v0.3.3-storage.json：来自标签 v0.3.3，提交 b55d3801b5640a640c39d8627e55cc37aefa95ef。

生成器为 .dev/audit/generate-release-legacy-fixtures.cjs，场景为同目录 release-legacy-scenario.txt。生成器从指定 Git 标签读取旧 store 及其依赖源码、打包后在固定时间和内存存储的 VM 中调用旧生产 actions，生成旧持久化信封和备份。没有用当前 actions 冒充旧版本，也没有读取用户真实资料。可通过以下命令重新生成：

~~~powershell
node .dev/audit/generate-release-legacy-fixtures.cjs
~~~

夹具包括多层任务与习惯、部分周期次数、隐藏及回收站、旧奖励余额和历史备注、自定义分类、调整过尺寸和位置的首页卡片、主题、流程和灵感。v0.3.0 流程使用当时的 type/note/warning/time 格式；v0.3.3 流程使用富文本和嵌套文件夹。

## 本轮发现并修复

1. 当前习惯执行归档后，冷启动会被历史迁移逻辑无条件改成暂停。现在保留 archived 状态，旧隐藏设置也保留。
2. v0.3.0 习惯缺少 timerAccumulated 时，其默认值被共享的一次性迁移标记阻止。现在每次读取都补齐缺失值，已有用时不变。

其他数据修复、MCP 幂等与权限、模板墓碑、导入布局等已有变更继续保留。未引入 v0.3.0 以前的平铺迁移重构。

## 验证结果

src/utils/releaseCompatibility.test.ts 新增 8 项均通过：

- 原 v0.3.0/v0.3.3 存储冷启动：旧奖励余额原样保留，真实业务数据、嵌套子项、个人纪念与备注不丢失，已有首页位置/尺寸/隐藏设置保持；新增待反馈卡片仅补在空位下方。
- 原 v0.3.0 备份在迁移标记已经存在时导入：多层子项仍保留，缺失计时字段补 0。
- 归档习惯冷重载后仍归档。
- 两个旧版本经导入、导出、再次导入和两次冷重载：任务与习惯没有重复、结构与数据稳定。v0.3.0 流程的父/子备注和警告转换为富文本后仍完整，时间和流程样式保留；v0.3.3 富文本和文件夹不变。再次完成任务只产生一条当前完成记录，旧奖励余额不重算、不新增。
- 第二账号读取 v0.3.0 数据不受第一账号旧标记影响，更新第二账号不会改写第一账号的存储字节。
- 导入写到最后一个资料分片时模拟失败，全部 10 个分片恢复到原始字节。

结合已有数据测试共 **9 个文件、154 项测试通过**，覆盖坏数据先拒绝、恢复失败/回滚失败明确报告、账号切换与异步操作、首页卡片筛选及隐藏、系统模板编辑/复制/墓碑、分类和去游戏化备份往返。app 与 node TypeScript 检查均通过。发布提交的全量测试、打包、安装运行与校验和由发布验收另行记录，本报告不把打包成功等同于安装成功。

## 兼容方向与恢复边界

本次确认的方向是受支持旧版本数据升级到新程序。旧奖励字段保留以避免破坏旧备份，但新程序不会继续结算它们。

新版本包含待反馈状态、多个独立筛选卡片、单任务底色、系统模板删除记录和 MCP 配置。v0.3.x 程序不理解这些新增语义，不能据此宣称“新数据可无损降级”。若要回退程序，应使用升级前由旧版本导出的备份，不能用新程序导出的资料覆盖旧版并期待全部新增功能保留。导入/云目录恢复仍是用户明确发起的覆盖恢复，不是自动双向合并；导入失败不会报告成功。
