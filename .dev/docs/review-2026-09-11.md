# v0.3.3 重新审查

日期：2026-09-11；代码基线：b55d380，main。审查不修改生产逻辑，不发布新版本。

范围：任务/习惯 store 与列表、Dashboard、抽屉、子项、SOP 转任务、备份/同步、日期刷新及开发规范。不是全仓无遗漏保证；没有进行浏览器或安装包交互验收。

证据：**复现**表示隔离测试实际调用生产代码；**静态确认**表示存在直接代码路径，尚无 UI 实测；**待复现**表示不能据现有证据确定根因。P1 为数据/核心功能问题，P2 为交互缺口和一般回归。

## P1 数据问题

### R1 跳过习惯后撤销会扣除没有发放的 XP（复现）

- 位置：src/stores/habitStore.ts:241、279；src/components/dashboard/HabitCard.tsx:98、112。
- 跳过写入 completed_today，但不发奖励；Dashboard 将其放入已完成组，仍提供完成撤销。undoComplete 重新计算并扣除 XP，同时减少历史完成次数/连续次数。
- 复现：角色已有 100 XP，创建习惯 → skipHabit → undoComplete，XP 低于 100。
- 验收：区分跳过和完成记录；撤销跳过不扣 XP、不修改其他完成记录，恢复跳过前状态。

### R2 习惯完成撤销不恢复日期和周期状态（复现 + 静态确认）

- 位置：src/stores/habitStore.ts:241、476。
- 完成再撤销，status 已 active，但 lastCompletedAt 未清理，getTodayStats().completed 仍为 1（复现）。lastDueAt、weeklyCompletionCount、容错和目标次数也没有按完成前快照恢复（静态确认）。
- 对 custom/biweekly，lastDueAt 还可能使撤销后的习惯不再到期显示。修改难度后再撤销又会按新难度计算扣分，不是原始奖励。
- 验收：保存那次完成的奖励和前状态，撤销后今日统计、周期资格、计数与实际历史一致。

### R3 跨天不重置子习惯和未达标次数（复现）

- 位置：src/stores/habitStore.ts:435。
- 完成 daily 习惯会递归勾选 subHabits；次日 resetDailyHabits 只改状态等字段，子项保持昨日勾选。另一个 targetCount=3 的 daily 习惯昨日做了 1 次，次日仍为 1。
- 验收：按周期重置子项及 currentCycleCount；同时覆盖 daily、跨周和自定义周期，不将所有周期一律按日清空。

### R4 恢复备份会丢失 Dashboard 布局（复现）

- 位置：src/utils/dataExport.ts:179；src/stores/dashboardStore.ts:61。
- 导入把所有切片写成 version:0；Dashboard 配置 version:3 且无 migrate。真实 persist hydration 拒绝该切片，恢复后的布局仍是默认布局。
- 复现：导出 tasks 卡片 col=7 的布局 → 重置布局 → 导入 → rehydrate，col 仍为 0，Zustand 报版本迁移错误。
- 验收：每个 store 的持久化版本分别处理；导出再导入并重新启动后布局、可见卡片和业务数据一致。

### R5 损坏备份可通过校验并覆盖有效数据（复现 + 静态确认）

- 位置：src/utils/dataExport.ts:87、119、179。
- tasks 只验证是数组，tasks:[null] 可以通过 parseImportText（复现）。嵌套子项和可选 SOP 切片同样缺乏完整结构校验；随后代码读取实体属性可能崩溃。
- 导入逐个 setItem，没有事务或失败回滚；中途配额/写入失败可能形成新旧切片混合状态（静态风险，未模拟存储耗尽）。
- 验收：写入前校验完整备份和嵌套深度；非法输入不改变任何切片，写失败可恢复原快照。

### R6 再次计时结算覆盖已有用时（复现）

- 位置：src/stores/taskStore.ts:186、352；类似赋值见 habitStore.ts 完成计时逻辑。
- 任务已有 actualMinutes=30，再开始计时 10 分钟并完成，最终变成 10。可通过已有 stopTimer 结算后重启计时，或完成后撤销再计时进入该路径。
- 验收：明确累计用时与本次用时的语义，连续多段计时和撤销再完成不静默丢失已记录时长；习惯按周期单独验证。

### R7 完成事件按标题查找，可能误删或无法撤销（静态确认）

- 位置：src/components/tasks/TaskItem.tsx:107、184、246；src/stores/habitStore.ts:272。
- 任务使用翻译后的完整标题匹配事件，习惯使用 title.includes。两个同名任务、习惯名包含关系、完成后改名或切换语言，会定位错误事件或找不到事件。XP 已撤回但事件还在时，成长趋势也会失真。
- 验收：稳定实体/完成记录 ID；同名、改名和切语言后只删除目标完成记录。

## P2 行为和交互

### R8 Dashboard 子任务禁止点击编辑（静态确认，对应用户反馈）

- 位置：src/components/tasks/SubTaskItem.tsx:141；TaskItem.tsx:623。
- compact 模式直接阻止 setEditing，且隐藏删除操作。用户看到相同子项却无法执行相同编辑动作。
- 验收：compact 只控制密度，支持一致的子项编辑入口；点击不会误触父项编辑。

### R9 子任务拖拽没有接入（静态确认，对应用户反馈）

- 位置：src/stores/taskStore.ts:304；TaskDrawer.tsx:282；TaskItem.tsx:622；SubTaskItem.tsx:178。
- reorderSubTasks/reorderNested 已存在，但这些渲染位置仅 map，没有子项 Reorder/drag 绑定。习惯 store 也没有对应的子习惯排序 action。
- 验收：指定层级内稳定排序、重载后保留、拖拽不会勾选/编辑/移动父项；任务习惯保持一致。

### R10 抽屉内复选框会默认提交表单（静态确认）

- 位置：src/components/ui/Checkbox.tsx:12；TaskDrawer.tsx:146、291。
- Checkbox 渲染 button 未指定 type，位于 form 内默认 submit；stopPropagation 不取消默认提交。点击子任务勾选同时可能触发 handleSubmit 和关闭抽屉。
- 验收：勾选仅更新子项，抽屉保持打开；Enter 编辑需单独覆盖输入法和表单隐式提交。
- 此问题不能直接解释用户“编辑时间重置子项”的反馈，两者不能合并定因。

### R11 SOP 转任务静默丢弃三级步骤（静态确认）

- 位置：src/stores/taskStore.ts:80、92；src/stores/createTaskFromSOP.test.ts:6。
- 编辑器支持三级 SOP，但转换只映射前两级，第三级写为空数组。测试复制了映射代码并断言三级被忽略，所以正常测试通过也未保护用户内容。
- 验收：支持的深度完整转换；确实不能转换的内容必须明确提示。测试调用实际 createTaskFromSOP action。

### R12 Dashboard 隐藏的流程/灵感卡片会在重载后再出现（静态确认）

- 位置：src/stores/dashboardStore.ts:62、70。
- 每次 hydration 都将 inspiration/flows 添加回 visibleCards，不区分首次迁移和用户主动隐藏。
- 验收：新增卡片的默认可见性只迁移一次，用户偏好重启后保留。

## 修复回验（2026-09-11）

- R1、R2：习惯保存完成/跳过快照，撤销恢复次数、日期、子项和原始奖励；跳过撤销不扣 XP，过期撤销按钮不能撤销新一轮完成。
- R3：按本地日历周期刷新次数、子项、计时；自定义多日周期保留周期内进度，跨周期重置。定时跨度采用日历天，不按固定 24 小时计算。
- R4、R5：恢复使用 Dashboard version 3，校验实体、嵌套结构和分组；仅导入数据字段，写入异常时尝试恢复所有原值。回滚本身失败会明确报错，不保证进程崩溃或断电原子性。
- R6：任务多段计时累计，不覆盖已记录用时。
- R7：新事件绑定实体和完成记录 ID；不再用翻译后的标题匹配撤销事件。旧事件不按猜测删除。
- R8、R9：共享任务/习惯子项编辑和拖动排序，Dashboard 子项支持点击编辑；多层子项保留就地添加入口。
- R10：复选框显式为非提交按钮，子项 Enter 编辑阻止表单隐式提交，并兼容输入法组合输入。
- R11：SOP 转任务递归保留三级步骤，测试改为调用真实生产 action。
- R12：用户隐藏的流程和灵感卡片重载后保持隐藏。
- 截图反馈：任务与习惯采用共享行过渡参数，Dashboard 撤销使用同一 Toast；紧急优先级增加感叹号和本地化文字。
- 用时反馈：修正无旧迁移标记时覆盖内嵌子项的分支。浏览器操作完成父任务、编辑实际用时为 25 分钟、保存和刷新后，两个子项仍完成。原反馈触发路径未完整复现，不把此迁移问题直接认定为唯一原因。
