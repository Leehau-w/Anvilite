# 待反馈撤销与多卡分类（2026-10-23）

支线：codex/legacy-review；本次小修纳入 v0.4.1 发布，沿用现有架构，不修改已发布 v0.4.0 标签或安装包。

## 修复与功能

- 根因：任务撤销完成原先固定回到 todo。现在仅从 waiting 完成时，持久化可选 completionReturnStatus:'waiting'；撤销后消费此标记并回到 waiting，计时保持停止。
- 其他任务继续恢复 todo。旧 done 记录没有保存完成前状态，仍恢复 todo，不根据标题、时间等猜测来源。已在旧版撤销而失去来源的记录需重新移入待反馈。
- 完成事件仍通过实体/完成记录 ID 关联；撤销只移除该次完成事件，用时、子项和旧奖励规则保持。实体或事件写入失败时保留原回执供重试；MCP沿用同一业务动作和幂等请求规则。
- 待反馈支持 waiting / waiting:<独立ID> 多卡片，新增卡片置于现有布局下方；统一标题，各自选择全部、单个或多个分类，可隐藏/恢复并保留筛选。
- 筛选只决定显示范围，不复制任务。投放时重读原任务；不匹配当前分类时显示提示，不改变任务状态和分类。空分类筛选保持为空。

## 兼容与数据

- completionReturnStatus 为可选字段，仅接受 waiting；旧 v0.3+ 数据没有该字段仍可读。
- waitingFilter 采用现有任务/习惯分类筛选结构，备份严格校验并限定于待反馈卡片。dashboard 持久化版本仍为3，备份版本不变。
- 旧布局、卡片位置尺寸、隐藏状态、显式全隐藏数组、旧备份省略 dashboard 均保留既有行为。导出/导入后冷重载保留多个卡片及完成来源。
