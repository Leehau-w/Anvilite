# 待反馈任务（2026-10-22）

用户后续微调：名称统一为“待反馈”，去掉任务标题下重复的紫色等待状态小字。状态操作、计时及备份规则保持。

## 范围与行为

基于 codex/legacy-review 的旧版问题修复，按用户要求增加一个合并的首页卡片和持久化 waiting 状态。用途是等待回信、反馈或外部进展，暂时无法主动推进的任务。沿用原任务、布局与持久化结构，没有引入大改或重构。

- 正常首页可抓住任务左侧小拖柄拖入卡片；右键菜单、任务悬停操作与编辑抽屉提供同一状态操作。布局编辑模式仍用于调整卡片，禁止接收任务。
- waiting 是原任务的新状态，不复制任务。任务列表独立分组，分类页、隐藏列表及分类卡片同步显示。
- 进入等待暂停活动计时，将本段秒数计入累计时间；保留已有用时、子项、备注、标签、优先级、分类和截止日期，不产生奖励。
- 恢复操作回到 todo，不自动开始计时。等待任务可直接完成，沿用完成/撤销奖励规则；已完成、隐藏、删除任务不能由拖入操作改成等待。
- 卡片显示所有可见、未删除的等待任务，包括无日期和未来日期任务。原首页主动任务卡片不再把等待任务列作待办或进行中。
- 备份校验接受 waiting，拒绝等待状态仍有活动计时和非法累计时间。导出、导入及同步恢复复用原有验证与回滚路径。

交叉审查额外复现并修复一个导入边界：旧账号的计时迁移标记已存在时，缺少计时字段的合法兼容备份不会再补默认值，恢复计时后可能产生 NaN 用时。现改为每次载入在原有兼容 map 中补齐计时与标签默认值；标记写入规则保留。新增实际 parse → apply → rehydrate → 恢复待办 → 计时 60 秒 → 完成回归，确认用时从 30 正确变为 31 分钟，既有标记保持。

## 首页兼容与拖放边界

新安装的默认布局使用原布局下方空位。已有布局缺少 waiting 时，只在旧布局最下方追加卡片，原卡片坐标、尺寸及隐藏状态保留；显式隐藏全部卡片的空数组保留。新卡片已存在但被用户隐藏后，重载不会重新显示。此前修复的缺字段导入布局回退仍保留。

原生拖放只从独立小拖柄开始，避免抢占任务排序和子项编辑。拖放会话以本页随机令牌和内存任务 ID 对应，拒绝外部文本、猜测 ID、取消后或已消耗的拖放。窗口失焦、拖动结束清理会话；拖出卡片、Escape、失焦清理高亮。
