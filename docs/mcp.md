# 通过 MCP 连接 Agent

本机 stdio MCP 让支持本机 stdio MCP 的 Agent 读取和操作 Anvilite 的任务、习惯与流程。软件需要保持打开。连接使用本机进程通信，不监听 TCP 网络端口。

## 开始连接

1. 打开 Anvilite 的“设置 → Agent 连接 · MCP”。
2. 开启本机 MCP。首次开启默认只读。
3. 按需为任务、习惯、流程分别勾选“读取”和“修改”。勾选修改会同时允许读取；关闭读取也会关闭该类修改。
4. 点击“复制 Agent 连接配置”，粘贴到你的 Agent 客户端的 MCP 设置中并连接。

复制的是常见的 mcpServers JSON 配置；使用其他配置格式的客户端，可以对应填写 command、args、env。配置使用应用自带的 Electron/Node 运行时，不需要额外安装 Node.js。开发源码运行前，先分别执行 npm ci 和 npm --prefix mcp ci 安装两个包的依赖，再执行 npm run build（包含独立 MCP 构建）。安装版和便携版已包含运行所需组件。

连接凭据只对当前账号、本次应用会话有效，不放进普通数据备份。修改权限会更换凭据，需要重新复制配置并重连；关闭 MCP、退出、切换账号或重新加载页面后，旧连接失效。重新打开软件不会自动恢复授权。

## 支持的内容

| 内容 | 读取 | 操作 |
| --- | --- | --- |
| 任务 | 列表筛选、分页、详情、子项及版本 | 新建、内容编辑、待反馈/恢复、开始/暂停、计时、完成/撤销、软删除/恢复 |
| 习惯 | 列表筛选、分页、详情、周期与子项 | 新建、内容与周期编辑、完成/跳过/撤销、暂停/恢复、归档、计时、软删除/恢复 |
| 流程 | 流程列表、文件夹、完整步骤与富文本 | 新建、标题/样式/步骤编辑、复制、移动、删除、转为任务；创建文件夹 |

流程步骤按现有 ID 合并修改：没有提到的步骤、说明和子步骤会保留；不带 ID 的新步骤追加到对应位置。首版不通过普通步骤修改隐式删除、移动或重排旧步骤。系统模板通过移动操作拖出时仍按原业务规则创建副本。流程转任务还需要任务修改权限。

任务和习惯的内容编辑只接受明确的业务字段，不允许直接改内部状态、完成次数、历史记录或整个底层存储。更改状态需要使用对应操作。

## Agent 应怎样调用

先调用 get_context 读取当前账号、权限和集合版本，再列表查询、读取详情。现有记录修改要带刚读取的 expectedVersion；新建要带集合版本。版本覆盖完整内容及当前会话，不依赖可能相同的更新时间。

每次修改必须带独立 requestId。同一操作重试必须原样使用同一个 requestId 和参数，已确认成功的重试返回原结果，不会再次执行；返回的旧结果不代表当前最新状态，后续编辑前应重新读取。

若返回版本冲突，应重新读取并基于新内容决定修改。分页期间集合变化会使旧游标失效，应重新查询。

如果断线、超时或存储异常造成结果未知，Agent 应使用 operations_get 查询原 requestId 并检查当前记录，不能换一个 ID 自动再做一次。应用会保留未确认的回执，并在无法确认写入时暂停本会话的后续 MCP 修改。需要重新加载应用、重新连接并读取当前内容后，才能作出新的操作决定；原未知请求仍不会被自动重做。

应用载入数据、切换账号、恢复备份或发现其他窗口更改相关数据时，旧请求会被拒绝。按照提示重新打开应用并连接即可。

首版每页最多读取 100 条记录，每个账号最多保留 2000 条修改回执；回执满额或本机存储不足时停止新的 MCP 修改，不会为了腾出空间遗忘旧请求。回执属于当前本机账号资料，不随普通业务备份迁移；新会话须重新读取版本，备份前的连接和版本不能直接继续写入。

MCP 通信可以完全在本机进行；Agent 读取的内容是否发送到云端，取决于所使用的模型和客户端。
